Unit 1: Introduction to Computers

Unit Overview: This unit introduces the basic concept of a computer, its characteristics, uses in various fields, types, generations, and the basic organization including CPU, memory hierarchy, registers, and I/O devices. It builds the foundation for understanding how computers work.

1.1 What is a Computer?

A computer is an electronic device that receives input, stores or processes the input as per user instructions, and provides output in a desired format. It can carry out sequences of arithmetic or logical operations automatically based on programs (sets of instructions). Computers are used in almost every field today, from simple devices like microwave ovens to complex systems like industrial robots and smartphones.

1.2 Characteristics of Computers

  • Speed: Computers can perform complex calculations at very high speed, much faster than any human being.
  • Accuracy: Computers produce 100% accurate results when given correct input and instructions.
  • Storage: Computers can store huge amounts of data in appropriate formats for future use.
  • Diligence: Computers can work for hours without any break or errors. They never get tired or bored.
  • Versatility: Computers can perform various types of tasks. No field today is untouched by computers.
  • Intelligence: Computers do not have their own intelligence. They work only according to the instructions given by the user.

1.3 Uses of Computers

Computers have become an essential part of modern human life. Some major areas of use include:

  • Education: Distance learning, research, online classes, and digital libraries.
  • Health and Medicine: Digitized medical records, ECG, radiotherapy, and diagnostic tools.
  • Financial Institutions: Banks use computers to store account holder information, manage cash flow, and provide online banking services.
  • Entertainment: Playing games, watching movies, listening to music, and creating digital art.
  • Transport System: Online reservation systems, traffic control, and navigation using GPS.
  • Businesses: Email communication, video conferencing, marketing, stock exchanges, and record keeping.
  • E-Commerce: Online shopping, electronic banking, and digital transactions.
  • Security and Defense: Designing missiles, satellite communication, GPS tracking, and criminal record maintenance.
  • Computer as Designer: Designing buildings, magazines, safety equipment, and using AI for creative work.

1.4 Types of Computers

Computers are classified on the basis of their size and use:

  • Desktop: Personal computer designed for regular use at a single location.
  • Laptop: Portable personal computer for mobile use.
  • Tablet: Touchscreen-based portable computing device.
  • Server: Powerful computer that provides services to other computers on a network.
  • Mainframe: Large, powerful computer used by big organizations for bulk data processing.
  • Supercomputer: The fastest and most powerful computer used for scientific and research purposes.

1.5 Generations of Computers

Generation Period Technology Used Examples
First 1942-1955 Vacuum Tubes ENIAC, UNIVAC-1
Second 1955-1964 Transistors IBM 700, IBM 1401
Third 1964-1975 Integrated Circuits (IC) IBM 370, IBM System/360
Fourth 1975-Present Microprocessors (VLSI) Apple Macintosh, IBM PC
Fifth Present & Beyond Artificial Intelligence (AI) IBM Watson

First Generation (1942-1955)

  • Used vacuum tubes for processing.
  • Very large in size, consumed a lot of energy, and heated quickly.
  • Required air conditioning and constant maintenance.
  • Not portable and not very reliable.

Second Generation (1955-1964)

  • Used transistors instead of vacuum tubes, making computers smaller and more reliable.
  • Used less energy, faster speed (microseconds), and wider commercial use.
  • Used Assembly language instead of Machine language.
  • Cooling system was still required; punch cards were used for input.

Third Generation (1964-1975)

  • Used Integrated Circuits (IC) which contained thousands of transistors on a single chip.
  • Smaller, faster (nanoseconds), more reliable, and less expensive.
  • Used mouse and keyboard for input. Supported high-level languages.
  • Air conditioning was still required.

Fourth Generation (1975-Present)

  • Used Microprocessors (VLSI technology) containing millions of electronic circuits.
  • Small in size, very powerful, fast, and cheapest among all generations.
  • No air conditioning required. Totally general purpose.
  • Supports all types of high-level languages.

Fifth Generation (Present & Beyond)

  • Based on Artificial Intelligence (AI).
  • Can understand spoken words and imitate human reasoning.
  • Uses sensors to respond to surroundings.
  • Scientists are trying to create computers with real IQ using advanced programming.

1.6 Basic Computer Organization

A computer system consists of the following main units:

  • Input Unit: Enters data and programs into the computer system. Examples: keyboard, mouse, scanner.
  • Storage Unit: Saves data and instructions permanently. Stores data before and after processing, as well as intermediate results.
  • Processing Unit (CPU): Performs arithmetic and logical operations. It takes data from storage, processes it, and sends results back.
  • Output Unit: Produces results in human-readable form. Examples: monitor, printer, speaker.
  • Control Unit: Directs and coordinates all operations of the computer. It determines the sequence of execution.

Central Processing Unit (CPU)

The CPU is the brain of the computer. It consists of two parts:

  • ALU (Arithmetic Logic Unit): Performs arithmetic operations (addition, subtraction, multiplication, division) and logical operations (comparison, decision making).
  • CU (Control Unit): Coordinates all computer operations, interprets instructions, and sends signals to other units for execution.

1.7 Memory Hierarchy

Memory in a computer is organized in a hierarchy from fastest and smallest to slowest and largest:

Level Memory Type Speed Size
1 (Fastest) Registers Fastest Smallest
2 Cache Memory Very Fast Small
3 Main Memory (RAM) Fast Moderate
4 (Slowest) Secondary Storage (Hard Disk) Slowest Largest

Types of Registers

  • MAR (Memory Address Register): Holds the memory addresses of data and instructions to be accessed.
  • Program Counter (PC): Keeps track of the next memory address of the instruction to be executed.
  • Accumulator Register: Stores the results produced by the system.
  • MDR (Memory Data Register): Contains data to be stored or data fetched from memory.
  • Index Register: Used for modifying operand addresses during program execution.
  • Memory Buffer Register (MBR): Holds data or instruction read from or written to memory.
  • Data Register: Temporarily stores data being transmitted to or from a peripheral device.

1.8 Input/Output Devices

  • Keyboard: Most common input device for typing data and instructions.
  • Mouse: Pointing device used to control cursor movement on screen.
  • Scanner: Converts printed/written information including photographs into digital form.
  • Track Ball: Similar to an upside-down mouse; the user spins the ball directly.
  • Light Pen: Input device used to draw lines or figures on a computer screen.
  • Optical Character Reader (OCR): Detects alphanumeric characters printed or written on paper.
  • Bar Code Reader: Reads bar codes and converts them into electric pulses for processing.
  • Voice Input Systems: Converts spoken words to machine language form.
  • Plotter: Output device used to produce graphical output on paper.
  • Digital Camera: Converts graphics directly into digital form using a CCD chip.

Unit 2: Techniques of Problem Solving

Unit Overview: This unit covers the concept of problem solving, problem definition, program design, flowcharting, decision tables, algorithms, and structured programming concepts. These are the fundamental tools used before writing any computer program.

2.1 Concept of Problem Solving

Problem solving consists of using methods in an orderly manner for finding solutions to problems. It is an art that can be mastered by learning the tools used for solving problems. The famous mathematician George Polya described four steps of problem solving in his book "How to Solve It?" (1945):

  1. Understand the Problem: Know what the problem is, what the input is, and whether there is enough information to solve it.
  2. Devise a Plan: Find a strategy to solve the problem. Strategies include trial and error, drawing a picture, looking for a pattern, making a list, solving a simpler problem, using a variable, or writing an equation.
  3. Carry Out the Plan: Execute the plan. If one strategy does not work, try a different one.
  4. Look Back: Examine the solution. Is the problem solved completely? Is there an easier way? This helps in solving future problems.

2.2 Problem Definition

Before writing a program, it is important to define the problem clearly. A systems analyst looks at the following issues:

  • What is the problem?
  • What is the input required for supporting the solution?
  • What is the expected output?
  • How do people solve the problem currently?
  • Can the problem be more effectively solved by software?

2.3 Program Design

Program design is the activity of progressing from a specification of some required program to a description of the program itself. It is one of the phases in the software life cycle. The input to this phase is a specification of what the program is required to do.

2.4 Flowcharts

A flowchart is a pictorial representation of an algorithm. It shows the step-by-step flow of a program using standard symbols connected by arrows.

2.5 Algorithm

An algorithm is a finite set of steps defining the solution of a particular problem. It is expressed in simple English or pseudo code. The word "algorithm" was derived from the name of the Persian mathematician al-Khwarizmi.

Characteristics of an Algorithm

  • Definiteness: Each step must be precisely stated, clear, and unambiguous.
  • Effectiveness: Every instruction must be capable of being carried out by a person with pen and paper.
  • Finiteness: The algorithm must stop after a finite number of instructions.
  • Input: The algorithm receives zero or more inputs.
  • Output: The algorithm produces at least one output.

Example: Algorithm to Add Two Numbers

Step 1: Start
Step 2: Read the first number (fno)
Step 3: Read the second number (sno)
Step 4: Add them: sum = fno + sno
Step 5: Display fno, sno, sum
Step 6: Stop

2.6 Structured Programming

C is called a structured programming language because it divides a large problem into smaller modules called functions or procedures. Each function handles a particular responsibility. The entire program is a collection of such functions, making it easy to understand, debug, and maintain.

2.7 Decision Tables

A decision table is a graphical method for explaining the logic of making decisions in tabular format. It consists of a set of conditions and a set of actions with different combinations of decisions. It is divided into four parts: Condition Stub, Condition Entry, Action Stub, and Action Entry.

Advantages of Decision Tables

  • Provides compact representation of the decision-making process.
  • Easier to understand a particular path of logic.
  • Can be changed according to the situation.
  • Best suited for calculating discounts, commissions, or inventory control procedures.
  • Promotes a logically complete and consistent problem definition.

Disadvantages of Decision Tables

  • Cannot express the complete sequence of operations to solve a problem.
  • If there are too many alternatives, it is difficult to list them.
  • Does not show the flow of logic for the solution.

2.8 Why Write Algorithm, Then Flowchart, Then Program?

The recommended sequence is: first write an algorithm, then draw a flowchart, and then write a program. This is because algorithms provide the systematic logic, flowcharts give the visual blueprint (like an architect's drawing before building), and programming is the actual implementation. Following this sequence makes development easier and helps in finding errors quickly.

Unit 3: Planning the Computer Program

Unit Overview: This unit covers programming methodologies (top-down and bottom-up), the concept of debugging, types of errors in programming, and documentation. These concepts help in planning and organizing a program before and after writing it.

3.1 Programming Methodologies

Top-Down Approach

In the top-down approach, we start with the overall problem and break it down into smaller sub-problems. Each sub-problem is then solved separately. It is also called stepwise refinement. This approach allows building solutions in a step-by-step manner, where complex details are handled only after the overall structure is understood.

Bottom-Up Approach

In the bottom-up approach, we identify lower-level tools and modules first, then compose them to develop a bigger program. The focus is on solving parts of the problem first, and then combining them to form the complete solution.

Parameter Top-Down Approach Bottom-Up Approach
Starting Point Starts from the main problem Starts from smaller modules
Focus Overall structure first Individual parts first
Decomposition Breaks problem into sub-problems Combines modules into bigger program
Detail Handling Details handled at the end Details handled at the beginning
Suitable For Large, complex problems Problems with reusable components

3.2 Debugging

Debugging is the process of finding and resolving defects or problems within a program that prevent correct operation. A "bug" means an error, and "debugging" means correcting the error.

Types of Debugging

  • Print Debugging (Brute Force): Using print/trace statements to watch the flow of execution. Also called "printf debugging" due to the use of printf function in C.
  • Backtracking: Starting from the statement where an error symptom was discovered, the source code is traced backward until the error is found. This can be tedious if many lines need to be traced.
  • Cause Elimination Method: A list of possible causes is created, and each cause is tested and eliminated until the actual error is found.
  • Remote Debugging: Debugging a program running on a system different from the debugger.

3.3 Types of Errors in Programming

Error Type Description When Detected Example
Syntax Error Related to grammar rules of the language At compile time Missing semicolon, misspelled keyword
Logical Error Program runs but produces wrong output At run time (wrong results) Using + instead of *
Run-time Error Occurs during program execution At run time (program crashes) Dividing by zero, memory leak

3.4 Documentation

Documentation is any written text, illustrations, or video that describes a software or program to its users. It is a critical process in the overall software development process, especially in modular programming where different modules are developed by different teams.

Guidelines for Documentation

  • Documentation should be from the point of view of the reader.
  • It should be unambiguous and without repetition.
  • Industry standards should be used.
  • Documents should always be updated.

Types of Software Documents

  • Operational Manual: Lists and describes all operations and their inter-dependencies.
  • Design Document: Gives overview of software and describes design elements in detail (DFD, ER diagrams).
  • Requirements Document: Lists all requirements and analysis of viability.
  • Technical Documentation: Documents algorithms, flowcharts, program codes, and functional modules.
  • Testing Document: Records test plan, test cases, validation plan, and test results.
  • List of Known Bugs: Lists bugs that cannot be removed immediately.

Internal vs External Documentation

4.2 History of C Language

  • C is a general-purpose, structured programming language developed in 1972 by Dennis Ritchie at Bell Labs, USA (AT&T).
  • It is an offspring of two earlier languages: BCPL (Basic Combined Programming Language) and B Language.
  • Until 1978, C was confined to Bell Labs. Dennis Ritchie and Brian Kernighan published "The C Programming Language" (K&R C).
  • C is classified as a Middle-Level Language because it combines features of both high-level and low-level languages.

4.3 Features of C Language

  • Simple and easy to learn.
  • Structured programming language (divides problem into functions).
  • Rich set of built-in operators and data types.
  • Supports pointers for direct memory access.
  • Portable - programs can run on different machines with little modification.
  • Efficient and fast execution.
  • Supports dynamic memory allocation.
  • Has 32 keywords.
  • Case-sensitive language.
  • Used to write operating systems (like Windows), applications, and database systems (like Oracle).

4.4 C Character Set

The collection of characters used in C programming includes:

  • Alphabets: A-Z, a-z
  • Digits: 0-9
  • White Spaces: Blank space, horizontal tab (\t), carriage return (\r), new line (\n), form feed (\f)
  • Special Characters: , . ; : ? ' " ! | / \ ~ _ $ % & ^ * - + < > ( ) [ ] { } #

4.5 C Tokens

The smallest individual units in a C program are called tokens. There are six types of tokens:

  1. Keywords: Reserved words with predefined meaning (e.g., int, float, switch, case). C has 32 keywords.
  2. Identifiers: Names given to variables, functions, and arrays (e.g., cost, amount).
  3. Constants: Fixed values (e.g., 25, 4.5).
  4. Strings: Sequence of characters in double quotes (e.g., "YCMOU").
  5. Operators: Symbols that perform operations (e.g., +, -, *, /).
  6. Special Symbols: [], {}, # etc.

4.6 Keywords in C (32 Keywords)

4.7 Identifiers / Variables

Each program element is given a name called an identifier. A variable is a data name used to store a data value.

Rules for Naming Identifiers

  • First character must be an alphabet or underscore (_).
  • Following characters can be letters, digits, or underscores.
  • No special characters except underscore are allowed.
  • Maximum length is up to 31 characters.
  • Blank spaces are not allowed.
  • C reserved words cannot be used as identifiers.

Valid: fno, _sno, get_num
Invalid: Gross Pay, 1no

Unit 6: Decision Making and Looping

Unit Overview: This unit covers control structures in C including decision-making statements (if, if-else, nested if, switch-case, conditional operator) and looping structures (for, while, do-while), along with break, continue, and goto statements.

6.1 Control Structures

Control structures change the flow of program execution:

  • Conditional Branching: Transfer of control based on a condition (if, switch).
  • Unconditional Branching: Transfer of control without any condition (goto).
  • Looping: Repeating a group of statements multiple times.

6.2 Decision Making Statements

Simple if Statement

Executes a block of code only if the condition is true.

if (condition)
{
    // Statement block (executed if condition is true)
}
// Statement-x (always executed)

if-else Statement

Provides both true and false paths.

if (condition)
{
    // True block
}
else
{
    // False block
}

Nested if-else Statement

An if statement inside another if statement. Used when multiple conditions need to be checked in a hierarchy.

if (condition1)
{
    if (condition2)
    {
        // Block A
    }
    else
    {
        // Block B
    }
}
else
{
    // Block C
}

else-if Ladder

if (condition1)
    statement1;
else if (condition2)
    statement2;
else if (condition3)
    statement3;
else
    default_statement;

Conditional / Ternary Operator

A shorthand for simple if-else statements.

// Instead of:
if (f > s)
    max = f;
else
    max = s;

// Use ternary operator:
max = (f > s) ? f : s;

switch-case Statement

A structured way to handle multiple choices. The switch expression is compared with each case value.

switch(expression)
{
    case value1:
        statements;
        break;
    case value2:
        statements;
        break;
    default:
        statements;
}

Note: The break statement is essential in each case to prevent "fall-through" to the next case. The default case handles values that don't match any case.

6.3 Looping Structures

for Loop (Counter-Controlled)

Used when the number of iterations is known in advance.

for (initialization; condition; increment/decrement)
{
    // Loop body
}

// Example: Print name 10 times
for(i = 1; i <= 10; i++)
    printf("YCMOU");

while Loop (Entry-Controlled / Top-Tested)

Condition is checked first, then the loop body executes. The loop may not execute at all if the condition is false initially.

while(condition)
{
    // Loop body
    // Update expression
}

// Example:
int i = 1;
while(i <= 10)
{
    printf("YCMOU");
    i++;
}

do-while Loop (Exit-Controlled / Bottom-Tested)

The loop body executes first, then the condition is checked. The loop executes at least once.

do
{
    // Loop body
} while(condition);

9.1 Need for Functions

A function is a sub-program or set of instructions written to perform a particular task. Functions make programs:

9.2 Scope and Lifetime of Variables

  • Global Variables: Declared outside all functions. Accessible by all functions in the program.

    int cube(int);

9.4 Call by Value vs Call by Reference

Parameter Call by Value Call by Reference
What is Passed Value of actual argument is copied to formal argument Address (reference) of actual argument is passed
Access to Original Cannot access original variable Can access original variable
Effect of Changes Changes to formal argument do NOT affect actual argument Changes to formal argument ARE reflected in actual argument
Pointers Required No Yes

Call by Value Example

void fun(int x)  // x gets a copy of a
{
    printf("%d ", x);
    x++;          // Changes only the copy
    printf("%d ", x);
}

void main()
{
    int a = 10;
    fun(a);       // Passes value of a
    printf("%d ", a);  // a is still 10
}

Call by Reference Example

void fun(int *x)  // x points to a
{
    printf("%d ", *x);
    (*x)++;         // Changes the original a
    printf("%d ", *x);
}

void main()
{
    int a = 10;
    fun(&a);        // Passes address of a
    printf("%d ", a);  // a is now 11
}

Unit 10: Pointers

Unit Overview: This unit covers the concept of pointers, declaring and initializing pointer variables, accessing addresses, pointer arithmetic, arrays and pointers, pointer to pointer, and pointers to functions.

10.1 Understanding Pointers

A pointer is a variable that stores the memory address of another variable. Since memory locations can be accessed using addresses, pointers allow direct manipulation of data in memory, making processing faster.

10.2 Declaring and Initializing Pointers

// Declaration
data_type *pointer_name;
int *p;       // p is a pointer to integer

// Initialization
int a = 10;
p = &a;       // p now stores address of a

// Accessing value using pointer (dereferencing)
printf("%d", *p);  // Output: 10 (value at address stored in p)

// Changing value using pointer
*p = 20;           // a now becomes 20

Key Operators

  • & (Address Operator): Returns the address of a variable. Example: &a gives address of a.
  • * (Indirection/Dereference Operator): Accesses the value at the address stored in a pointer. Example: *p gives value at address stored in p.

Printing Address of a Variable

int i = 3;
printf("Address of i = %u", &i);   // %u for unsigned (address)
printf("Value of i = %d", i);
printf("Value of i = %d", *(&i));  // Same as i

10.3 Pointer Arithmetic

Valid Operations

  • Addition of integer to pointer: p1 + 3
  • Subtraction of integer from pointer: p1 - 2
  • Subtraction of two pointers: p1 - p2
  • Increment/Decrement: p1++, --p2
  • Comparison (if same data type): p1 == p2, p1 < p2

Invalid Operations

  • Addition of two pointers: p1 + p2 (Invalid)
  • Multiplication of pointers: p1 * p2 (Invalid)
  • Division of pointers: p1 / p2 (Invalid)

Note: When a pointer is incremented, it moves by the size of its data type. For example, if int *p has value 100 and int is 2 bytes, then p++ makes p = 102 (not 101).

10.4 Arrays and Pointers

The name of an array is a constant pointer to its first element.

int a[5] = {10, 20, 30, 40, 50};
int *p;
p = a;      // p points to a[0]
// OR
p = &a[0];

// Accessing elements using pointer
printf("%d", *p);      // 10
printf("%d", *(p+1));  // 20
printf("%d", *(p+2));  // 30

Array of Pointers

int *p[5];  // p is array of 5 integer pointers

10.5 Pointer to Pointer

A pointer that stores the address of another pointer variable.

int data = 20;
int *p1 = &data;
int **p2 = &p1;     // p2 is pointer to pointer

printf("%d", **p2);  // Output: 20

10.6 Pointers to Functions

Pointers can be used with functions in two ways:

  1. Functions taking pointers as parameters:
    void swap(int *p1, int *p2);
  2. Functions returning a pointer:
    int *largest(int *, int *);

11.1 Introduction to Structures

A structure is a collection of dissimilar elements (different data types) grouped together under a single name. Unlike arrays (which store same type), structures can hold elements of different data types.

struct stud s = {1, "Raj", 5.5};

    int rollno;

11.4 Array of Structures

When we need multiple records of the same structure type, we use an array of structures.

{
    int rno;
    char name[20];

} s[10];  // s is an array of 10 structures

// Accessing elements

s[0].marks = 85;

11.5 Nested Structures

A structure declared inside another structure is called a nested structure.

struct student
{
    char name[20];
    int rollno;
    struct date
    {
        int day;
        int month;
        int year;
    } birthdate;

11.7 Unions

A union is similar to a structure but only one of its members can be used at a time. All members share the same memory area, so only one member is active at any given time.

The variable u1 will be allocated memory equal to the size of the largest member (in this case, 5 bytes for char s[5] or the size of int, whichever is larger).

Unit 13: Storage Classes

Unit Overview: This unit covers the concept of storage classes in C, which determine the scope, lifetime, memory location, and default initial value of variables. The four storage classes are: auto, static, extern, and register.

13.1 What are Storage Classes?

Storage class determines the following about a variable:

  • Where the variable is stored (memory or CPU register).
  • Default initial value (garbage or zero).
  • Scope (where the variable can be accessed).
  • Lifetime (how long the variable exists in memory).

13.2 Automatic Storage Class (auto)

  • Storage: Main memory (RAM).
  • Default Value: Garbage value.
  • Scope: Local to the function/block where declared.
  • Lifetime: Exists only while control is within the block.
  • Keyword: auto (default, usually omitted).
void func()
{
    auto int x;  // Same as: int x;
    // x contains garbage value
}

13.3 Static Storage Class (static)

  • Storage: Main memory.
  • Default Value: Zero (0).
  • Scope: Local to the function/block (if local static) or file (if global static).
  • Lifetime: Exists throughout the entire program execution. Retains value between function calls.
  • Keyword: static.
void count()
{
    static int x = 0;  // Initialized only once
    x++;
    printf("%d ", x);
}

// Calling count() 3 times prints: 1 2 3
// Without static, it would print: 1 1 1

Types of Static Variables

  • Local Static: Has block/function scope, retains value between calls.
  • Global Static: Visible only within the file where defined (not in other files).

13.4 External Storage Class (extern)

  • Storage: Main memory.
  • Default Value: Zero (0).
  • Scope: File scope (available to all functions in the file).
  • Lifetime: Exists as long as the program is running.
  • Keyword: extern.
int n = 5;  // Global variable (defined outside all functions)

void main()
{
    extern int n;  // Declaration (tells compiler n is defined elsewhere)
    printf("%d", n);
}

void display()
{
    extern int n;  // Can access n here too
    printf("%d", n);
}

Advantages of Global Variables

  • Simplifies communication between functions.
  • No need to pass them as arguments.

Disadvantages

  • Any function can modify them, leading to unexpected changes.
  • Makes debugging difficult.

13.5 Register Storage Class (register)

  • Storage: CPU registers (fastest storage).
  • Default Value: Garbage value.
  • Scope: Local to the function/block.
  • Lifetime: Exists as long as control is within the block.
  • Keyword: register.
register int i;  // Suggests compiler to store in CPU register
// Faster access than normal variables

Limitations of Register Variables

  • Limited number of CPU registers available.
  • Cannot use address-of operator (&) on register variables.
  • Cannot use pointers with register variables.
  • Compiler may ignore the register request and store in memory instead.

13.6 Summary of Storage Classes

Storage Class Storage Default Value Scope Lifetime Keyword
Automatic Memory Garbage Block/Function Within block auto
Static Memory Zero Block/File Entire program static
External Memory Zero File (Global) Entire program extern
Register CPU Register Garbage Block/Function Within block register

Exam Focus / Key Takeaways

  • Four storage classes: auto, static, extern, register with their properties.
  • Static variables retain values between function calls (key difference from auto).
  • Register variables cannot use & operator or pointers.
  • extern keyword used to declare global variables across files.
  • Default values: auto/register = garbage, static/extern = zero.
  • Difference between auto and static storage class.

Unit 14: The C Preprocessor

Unit Overview: This unit covers the C preprocessor, its features, macro expansion, macros with arguments, macros vs functions, file inclusion, and conditional compilation directives.

14.1 Introduction to Preprocessor

The preprocessor is a program that processes the source code before it is given to the compiler. It takes action based on special instructions called preprocessor directives which begin with #.

Tasks Performed by the Preprocessor

  • Joins lines ending with a backslash (\) into a single line.
  • Divides the program into a stream of tokens.
  • Removes comments and replaces them with a single space.
  • Processes preprocessor directives and expands macros.

14.2 Macro Expansion (#define)

A macro is a fragment of code that is given a name. Whenever the name is used in the program, it is replaced by the macro definition.

// Simple macro (object-like macro)
#define PI 3.14
#define MAX 100

// Usage in program
area = PI * r * r;    // Replaced as: area = 3.14 * r * r;
for(i = 0; i < MAX; i++)  // Replaced as: for(i = 0; i < 100; i++)

14.3 Macros with Arguments (Function-like Macros)

Macros can take arguments, making them look like functions.

#define HALFOF(x)  x/2
#define SQR(x)     x*x
#define MAX(x,y)   ((x) > (y) ? (x) : (y))

// Usage
result = HALFOF(10);     // Replaced as: result = 10/2;
ans = SQR(a);            // Replaced as: ans = a*a;
big = MAX(5, 10);        // Replaced as: big = ((5) > (10) ? (5) : (10));

Important: Always enclose macro arguments in parentheses to avoid unexpected results. For example, HALFOF(10+2) without parentheses would give 10+2/2 = 11 instead of (10+2)/2 = 6.

14.4 Multiline Macros

Use backslash (\) at the end of each line to continue a macro on the next line.

#define design for(i=1;i<=5;i++){\
                    for(j=1;j<=i;j++){\
                        printf("*");}\
                    printf("\n");}

14.5 Macros vs Functions

Parameter Macro Function
Size Usually small in size Can contain several lines of code
Processing Preprocessed (text replacement) Compiled
Code Insertion Code replaces macro name (inlined) Function code is not inserted; call is made
Program Size Increases (code duplicated at each use) Does not increase
Execution Speed Faster (no function call overhead) Slower (function call and return overhead)
Type Checking No type checking (risk of errors) Strict type checking
Best For Small, repeated code Large, complex code

14.6 File Inclusion (#include)

The #include directive inserts the contents of a header file into the source code.

#include <stdio.h>    // Searches in standard directories
#include "myhead.h"    // Searches in current directory first, then standard

14.7 Conditional Compilation

Conditional compilation allows selective compilation of code based on conditions. It is useful for platform-specific code, debugging, and feature flags.

Preprocessor Directives for Conditional Compilation

  • #if: Tests if a compile-time condition is true.
  • #ifdef: Returns true if the macro is defined.
  • #ifndef: Returns true if the macro is NOT defined.
  • #else: Alternative for #if.
  • #elif: Else-if combination for #if.
  • #endif: Ends preprocessor conditional block.
  • #undef: Undefines a previously defined macro.
// Example: Conditional compilation
#define DEBUG 1

#if DEBUG
    printf("Debug mode is ON");
#else
    printf("Debug mode is OFF");
#endif

// Example: #ifdef
#ifdef WINDOWS
    #include <windows.h>
#else
    #include <unistd.h>
#endif

// Example: #ifndef (include guard)
#ifndef MYHEADER_H
#define MYHEADER_H
    // Header contents
#endif

14.8 Other Preprocessor Directives

  • #pragma: Compiler-specific directives.
  • #error: Generates a compilation error message.
  • #line: Resets the line number and filename for error messages.
